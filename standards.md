# Architecture and engineering standards

These rules apply to every project. A project may deviate only with an entry in
[`docs/engineering-decisions/`](../engineering-decisions/).

## Layering

- **Ingestion** reads from a source and lands data unchanged, adding only lineage
  metadata (source, batch id, ingestion timestamp).
- **Transformation** is pure and deterministic: same input, same output. Business logic
  lives in functions that can be unit-tested without a cluster, database or network.
- **Validation** is explicit and produces a result object (passed / failed / quarantined
  rows with reasons), never a silent drop.
- **Storage** code is the only layer that knows file formats, table names or connection
  details.

## Pipeline requirements

1. **Idempotent.** Re-running a batch for the same input window must not change the
   outcome. Writes use merge/upsert or partition overwrite, never blind append.
2. **Incremental by default.** Full refresh is a documented fallback, not the normal path.
3. **Observable.** Every run emits structured logs with run id, row counts in/out,
   rejected counts and duration.
4. **Failure-aware.** Transient errors are retried with backoff; data errors are
   quarantined with a reason; neither is swallowed.
5. **Configurable without code changes.** Environment variables or config files only.
   No credentials, hostnames or paths in source.

## Code

- Python 3.11+, type hints on public functions, formatted and linted with Ruff
  (configuration in [`pyproject.toml`](../../pyproject.toml)).
- Shared helpers live in [`shared/`](../../shared/); projects must not copy them.
- Tests: pytest (unittest-style tests are also accepted). Unit tests need no network or
  containers; integration tests are marked and documented in the project README.
- Dependencies are pinned per project in `requirements.txt` only after being installed
  and tested.

## Diagrams

- Mermaid (`architecture.mmd`) is the source of truth and is also embedded in the
  project README so GitHub renders it. Exported images are optional and only committed
  when they were generated from the committed source.
- Diagrams show the real implementation. Components that are only authored (for example
  Terraform that was never applied) are drawn with a dashed outline and labelled.

## Data

- All datasets are synthetic, generated by seeded scripts committed to the repository.
  Generators are deterministic given a seed.
- Schemas live in `data/schemas/` and are enforced in code, not only documented.
- Data dictionaries follow [`docs/data-dictionaries/README.md`](../data-dictionaries/README.md).

## Security

- `.env` files and key material are git-ignored; `.env.example` documents every variable.
- `scripts/check_secrets.py` runs in CI as a safety net.
- Least privilege in IaC: no wildcard roles, secrets only via Key Vault references.
